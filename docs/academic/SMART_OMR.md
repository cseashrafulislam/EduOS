# Smart OMR — Issue #130, examination workflow

**Scope:** An optional camera/image-assisted *review draft* for the existing Assessment module. `Assessment`, `AssessmentSubject`, `StudentSubjectRegistration`, `StudentAssessmentMark`, `AssessmentComponent` and their controlled mark review/publication rules remain authoritative. OMR must not create a second grading engine or overwrite a locked/published grade.

## Recognition and geometric contract

`OmrBubbleRecognitionPolicy` classifies bounded, pre-aligned measured dark pixels (4/5 options, up to 200 raw question measurements). `OmrImageRecognition` performs a safe first-pass scan of **the EduOS-generated straight and properly aligned form only**, currently **up to 50 questions per printable page**. PNG/JPEG <=5 MB, <=16 MP, expected aspect ratio, four fiducials, opaque pixels and white-page lighting samples must pass. Skewed/cropped/rotated/perspective scans require recapture, not speculative correction. Machine results are `Single`, `Blank`, `LowConfidence`, or `Ambiguous`; every sheet requires independent human review. This is not arbitrary camera image OCR, automatic roll-number recognition or a promise of zero misreads.

## Full-stack workflow implemented in this change set (pending CI acceptance)

1. Manager seals a tenant-owned, component-specific answer-key template. There is no edit/soft-delete API; SQL and EF enforce immutability. The printable SVG has a UUID, four fiducials and hand-written student-roll line.
2. Manager or assigned teacher uploads a PNG/JPEG scan to the existing private scanned `FileAsset` service (`tenant-{tenant}/omr/...` namespace); a capture verifies actual private path, SHA-256, clean scan, uploader, authorized component and approved current student enrollment. Duplicate request/file/student-template combinations are rejected at SQL unique boundaries.
3. Original image remains private. A distinct authorized reviewer must inspect the original printed form/roll and every answer, check the identity confirmation box, and record a correction reason. Suggestions never post themselves. `OmrSheets` rowversion protects `Captured -> Reviewed -> Posted` transitions, while `OmrSheetEvents` records immutable user, request, answer, reason and time.
4. An exam manager explicitly posts a reviewed sheet. Posting is one serializable transaction through **existing** `SaveMarksRegisterAsync` and `SaveComponentMarkAsync` with registration/attempt, instructor, grade, lock and publication validation. The canonical register remains the only mark source. Existing component marks and unreconciled or manually entered subject totals cannot be overwritten; failure rolls back all changes. Request keys make successful posting retries idempotent.
5. `AssessmentAdministration/Omr` provides responsive English/Bangla review, notice, printed-sheet link and Help Drawer. Manager-only Excel/PDF *internal preparation* export uses the live canonical posted marks, selected field allowlist, student tenant/campus scope and bounded SQL queries. Files are private responses with no-store headers, named **not a direct board submission**. `Omr:QuestPdfLicense` must explicitly be configured to the organization's licensed QuestPDF tier (`Community`, `Professional` or `Enterprise`) before PDF export; no license tier is assumed.

## Operational limitations and QA gates

- Keep issue #130 open until hosted build/unit tests, real SQL migration/rollback, authenticated bilingual mobile/desktop browser, cross-tenant/file-IDOR, concurrent duplicate/rowversion and actual aligned scan/photo UAT are independently green. An `OmrImageRecognition` unit test is not an end-to-end camera acceptance test.
- Only existing safely aligned EduOS forms are supported (up to 50 questions per page). Unrelated commercial sheets, multi-page physical batches, OCR of student ID and tilted mobile photographs are explicitly unsupported; staff verify the student identity by comparing the original roll with the chosen registration before approval.
- Post-review amendments of a previously posted mark must use the existing controlled assessment marks-amendment/grade correction workflow; never alter posted OMR evidence or recalculate locked results.
- OMR originals are private evidence. No unaudited automatic deletion or TTL applies, and **policy-approved retention expiry, legal hold and safe confidential purge remain a separate operational gate**. Until an approved institutional retention process exists, the system preserves these records and administrators must not delete backing files manually.
- Migration `20261108090000_SmartOmrEvidence` is additive. Run the normal CI SQL migration/schema drift and rollback/snapshot checks before deployment. Do not run destructive migration Down against live evidence.
