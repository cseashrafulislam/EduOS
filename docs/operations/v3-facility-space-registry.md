# V3 Facilities — campus operational space registry (first Issue #107 slice)

This first Facilities vertical slice introduces a **distinct** tenant/campus-scoped operational space registry, not a duplicate academic Room, HostelRoom, Asset or InventoryLocation. Facilities has its **own** product module and feature code, both opt-in: it is deliberately absent from institution-type defaults and from plan-feature grants. Platform administrators must explicitly assign the FACILITIES feature to an appropriate plan, and an authorized tenant administrator must enable the module. Pilot-release authorization also excludes it. Existing V1/V2 and Inventory/Finance ledgers are unchanged.

API: GET /api/facilities/spaces (bounded pagination, optional authorized campus filter), POST /api/facilities/spaces, PUT /api/facilities/spaces/{id} (mandatory rowversion). MVC page: /FacilitySpaces/Index. Tenant/campus grants are rechecked for both source and destination on edits; an unknown or unauthorized campus returns 403. Space code uniqueness is enforced per tenant and campus; retries with identical payload return the existing space. The campus foreign key includes TenantId, and every space change enters the existing DbContext audit pipeline. The responsive bilingual page offers working create/edit/search/print controls; no stock or Finance posting is exposed.
