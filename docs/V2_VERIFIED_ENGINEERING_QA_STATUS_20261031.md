## 2026-10-31 additive paid-period clearance engineering pass

The implementation in this working tree adds an **approved Finance clearance** for Hostel `UpcomingStartReschedule` and Transport `UpcomingRiderExtension` when charged/posted exposure exists. This deliberately reuses the existing campus-configurable `DailyProrated` / `FixedMonthly` / `Manual` quote and override policy, tenant/campus/rowversion exposure checks, independent maker-checker review, exact-operation/date binding, transactionally single-use consumption and idempotency receipts. The new check-constrained migration adds an operation enum value and separately records signed **suggested** and **approved** adjustments without changing earlier approved credit semantics.

The Finance reviewer must explicitly attest a **zero** adjustment or link a separately created, independently approved, posted, BDT manual journal whose reference is `HOSTEL-CLEARANCE-{id}` / `TRANSPORT-CLEARANCE-{id}`, whose balanced student receivable leg matches the signed amount, and which is not reversed or linked to the other clearance module. This implementation **does not create or update a student invoice, credit note, payment, cash refund or journal**. Any needed invoice/credit-note reconciliation remains Finance-owned and must be evidenced before operating a paid amendment. The UI now accepts the approved clearance ID for the operation. Preview/quote is not approval.

### Reproducible implementation gaps; do not report 100%

**2026-10-31 targeted engineering follow-up (after this original checkpoint):** the existing Finance reservation `change-review` now calculates a **read-only, tenant/campus-policy-aware period quote** from the actual current and proposed dates. `DailyProrated` uses inclusive days and each month's actual length; `FixedMonthly` counts distinct calendar months; `Manual` and open-ended periods are explicitly unquoted and require Finance review. It returns separate current/proposed amounts and a signed delta (positive possible charge, negative possible credit), and the existing Finance UI displays the calculation mode/basis without converting the quote to a journal, invoice, permission or paid refund. Targeted .NET and JavaScript regressions cover this. **This is a prerequisite for an approved billing amendment, not a completed adjustment workflow**; both Operations charge-bearing guards remain intact.

**Owner's dynamic Auto + Manual policy follow-up:** the same quote review now accepts an optional **signed manual adjustment** and substantive override reason through an antiforgery-protected POST body. The campus's existing `DailyProrated` / `FixedMonthly` / `Manual` policy and `AllowManualOverride` decide whether an amount can be selected; automatic suggestions remain visible alongside any manual estimate. Server validation enforces permission, two-decimal monetary precision, signed range and a 20-1000-character reason. Legacy read-only GET calls still work for automatic estimates but reject manual amounts/reasons to avoid sensitive query strings. Added .NET policy and tenant-scoped service regressions and a JavaScript UI contract. **Preview figures remain estimates, not approval, invoice, credit note, refund or posted journal.** The newer clearance workflow above handles a narrower set of charged operations, but still does not automatically issue invoices or credit notes.
